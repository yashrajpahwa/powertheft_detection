HOW THE TFLITE THEFT-DETECTION MODEL WORKS
==========================================

Model file : models/theft_int8.tflite   (64 KB, full int8 quantized, 37,216 parameters)
Task       : once per day, classify a consumer's 24 hourly meter readings into
             7 classes: Normal, Theft1, Theft2, Theft3, Theft4, Theft5, Theft6
Data       : TDD2022 (df.csv), 64 consumers (16 building types x 4), 365 days each,
             10 hourly channels (6 electricity + 4 gas sub-meters, in kW)


1. THE CORE IDEA
----------------
In the dataset, theft is applied to a whole DAY, and each type leaves a signature
that only shows up when today is compared with the past:

  Theft1  whole day multiplied by a factor 0.1-0.8   -> sudden drop vs. history
  Theft2  all readings zero for a random interval    -> runs of zeros
  Theft3  each hour multiplied by its own random     -> jagged, noisy version of
          factor 0.1-0.8                                the normal daily shape
  Theft4  each hour = random fraction of the mean    -> normal daily shape is lost
  Theft5  replaced by a 24 h rolling average         -> unnaturally smooth curve
  Theft6  exact copy of YESTERDAY (replay attack)    -> today == yesterday

So the model looks at TODAY together with YESTERDAY and a 7-DAY HISTORY AVERAGE.
A single hour on its own isn't enough to tell most of these types apart.


2. PIPELINE (what happens for one day)
--------------------------------------

   raw readings (last 8 days x 24 h x 10 channels)
          |
          v
   [Python preprocessing - src/train_cnn.py: make_inputs(), nn_features()]
          |
          +--> input "seq"  (24 x 40)   hourly profiles
          +--> input "lvl"  (10)        consumption level
          +--> input "feat" (180)       engineered daily statistics
          |
          v
   quantize each input to int8   (q = round(x / scale + zero_point))
          |
          v
   [int8 TFLite model]  -->  7 class scores (int8)  -->  argmax = predicted class
                                                          (class 0 = Normal, 1-6 = theft)


3. MODEL INPUTS IN DETAIL
-------------------------
Let, per channel c:
  x  = today's 24 hourly values
  p  = yesterday's 24 hourly values
  h  = per-hour average of the previous 7 days (fewer at the start of the year)
  s  = mean of h over the day + 0.001   (the consumer's "normal level")

a) seq  (24 hours x 40 values)
   For each of the 10 channels, 4 curves, each divided by s:
       x/s,  p/s,  h/s,  |x - p|/s
   Dividing by s makes a hospital and a small office look alike: the model
   learns SHAPES and RATIOS, not absolute kW. Values are clipped to [0, 8].
   The |x - p| curve is exactly zero for a replayed day (Theft6).

b) lvl  (10 values)
   log(1 + s) per channel: tells the model the absolute size of the load.

c) feat  (180 values = 18 statistics x 10 channels)   [src/features.py]
     log_mean      log(1 + mean of today)
     ratio_prev    log(today mean / yesterday mean)
     ratio_hist    log(today mean / history mean)          -> Theft1
     cv, cv_hist   std/mean of today and of history        -> Theft5 (low)
     min_rel       min / mean
     max_rel       max / mean
     n_zero        number of zero hours                    -> Theft2
     zero_run      longest run of zero hours               -> Theft2
     rough         mean |2nd difference| / mean            -> Theft3/4 (high),
     rough_ratio   roughness today vs. history                Theft5 (low)
     diff_prev     max |today - yesterday| / mean          -> Theft6 (= 0)
     corr_prev     correlation(today, yesterday)           -> Theft6 (= 1)
     corr_hist     correlation(today, history shape)       -> Theft4 (low)
     corr_rev      correlation(reversed today, history)
     lr_mean       mean of log(today/history) per hour     -> Theft1
     lr_std        std  of log(today/history) per hour     -> Theft3
     step_max      largest hour-to-hour jump / mean
   Each feature is then squashed with  sign(f) * log(1 + 100*|f|)  so extreme
   values don't dominate. Exactly-zero values (e.g. diff_prev of a replay) stay
   exactly zero.

Day 0 of a consumer has no history, so it isn't classified.


4. NETWORK ARCHITECTURE (inside the .tflite)
--------------------------------------------
  seq (24 x 40)
    -> Conv1D 48 filters, kernel 3  + BatchNorm + ReLU
    -> 3 residual blocks, each:
         SeparableConv1D 48, kernel 3, dilation 2 / 4 / 8  + BatchNorm
         add to block input (skip connection) + ReLU
       (dilations 2,4,8 let the network "see" the whole 24 h day)
    -> GlobalAveragePooling (48)  and  GlobalMaxPooling (48)

  feat (180) -> Normalization (mean/std learned from training data, built in)

  concatenate [avgpool 48, maxpool 48, lvl 10, normalized feat 180] = 286
    -> Dense 64 + ReLU -> Dropout 0.2 (training only)
    -> Dense 64 + ReLU
    -> Dense 7 + Softmax  -> class probabilities

The convolution branch learns hour-by-hour shape patterns (smoothness,
jaggedness, zero intervals, similarity to yesterday). The feature branch gives
precise daily statistics. The dense layers combine both.

TFLite operators used: CONV_2D, DEPTHWISE_CONV_2D, FULLY_CONNECTED, ADD, MEAN,
REDUCE_MAX, CONCATENATION, SOFTMAX, SUB, MUL, RESHAPE, EXPAND_DIMS,
SPACE_TO_BATCH_ND / BATCH_TO_SPACE_ND (used for the dilated convolutions).
All are standard builtins supported by TensorFlow Lite Micro.


5. QUANTIZATION (float32 -> int8)
---------------------------------
Method: post-training full-integer quantization (src/export_tflite.py).
  - 1,000 training days were used as a "representative dataset" so the
    converter could measure the value range of every layer.
  - All weights AND activations are int8. Inputs and outputs are int8 too.
  - Size: 157 KB (float32) -> 64 KB (int8), about 2.5x smaller.

Input/output quantization parameters (real = scale * (q - zero_point)):
  seq    scale 0.03137  zero_point -128   (covers 0 .. 8)
  feat   scale 0.09945  zero_point  -56
  lvl    scale 0.14287  zero_point  -26
  output scale 0.00390625 (=1/256)  zero_point -128   (covers probabilities 0 .. 1)

To run it you quantize each input with q = clip(round(x/scale + zero_point), -128, 127),
invoke the interpreter, and take argmax of the output (src/run_tflite.py does this).

Accuracy cost of quantization: 97.94% (float) -> 97.89% (int8), only 0.05 points.


6. TRAINING
-----------
  - Loss: sparse categorical cross-entropy, with class weights to balance the
    rare theft classes against the 59% Normal days.
  - Optimizer: Adam, learning rate 0.003 with cosine decay, 60 epochs, batch 128.
  - Day label = the dominant theft label of the day (Normal if none).
  - Leak-free split: whole CONSUMERS are held out. Fold 3 (16 consumers, one of
    each building type) was never seen in training and is used for testing.


7. RESULTS (int8 model)
-----------------------
Real held-out consumers (5,824 days):
  7-class accuracy 97.89%, macro-F1 0.970, theft-vs-normal accuracy 98.88%

Synthetic test (src/synth_test.py, 17,472 days per scenario):
  realistic theft injection ........... accuracy 98.68%
  new consumers (x0.2-5 scale, noise) . accuracy 98.25%
  unseen variants (flat-mean T5,
    reversed-day T6) .................. accuracy 92.27%
     (a REVERSED day isn't detected, because the training data's Theft6 is
      always a replay of yesterday. Fix: add reversal to training.)
